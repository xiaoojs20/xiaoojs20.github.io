这两年，我越来越觉得，选择电脑和手机的逻辑和以前不太一样了。

选择个人设备时，我会越来越关注三个问题：

- **它能否帮助 AI 更好地了解我**
- **能否让 AI 更方便地替我做事**
- **能否灵活地利用本地和云端的算力**

以前买电脑，关心的是 CPU、显卡、屏幕、重量和价格；买手机，关心的是拍照、续航、系统流不流畅。现在频繁使用 AI 之后，我会额外考虑几个具体的问题：这台电脑能不能很好地运行 Agent？新的 AI 工具能不能第一时间用上？手机里的日程、健康数据和个人记忆，能不能被 AI 利用？

如果把这些因素放进来重新评价消费电子产品，Mac 和 iPhone 的优势会比以前更加明显。更有意思的是，这个判断并不依赖于 Apple Intelligence 有多强。我甚至认为，哪怕苹果自己没有做出最领先的大模型，它的设备也可能是 AI 时代相当好的选择。

## 个人计算设备的评价标准变了

过去，人打开软件、输入指令、执行操作，电脑是人的工具。ChatGPT 出现以后，人开始向 AI 咨询，得到答案，再自己完成操作。Agent 则在改变下一步：人提出目标，AI 自己调用工具、操作软件、产出结果。

这里有三个问题：AI 知不知道我的情况，能不能替我做事，以及在哪里完成计算。分别对应 Context、Action 和 Compute。用这三个维度去看电脑和手机，会得到一套与过去不同的评价标准。

| 维度 | 过去主要关心 | AI 时代额外关心 |
| --- | --- | --- |
| 硬件 | 软件和游戏运行性能 | 模型推理、内存容量、能效 |
| 操作系统 | 人操作软件的体验 | Agent 能否访问工具、独立执行 |
| 软件生态 | 应用数量与质量 | AI 工具的适配速度与完整性 |
| 个人数据 | 记录、备份、同步 | 能否转化为可用的个人上下文 |

下面分别谈 Mac 和 iPhone。

## Mac：AI 时代的生产力终端

### AI 软件生态的先发优势

AI 行业有一个挺有意思的现象：不少新产品最先适配的是 Mac。2026 年 2 月，OpenAI 发布 Codex App，首先支持 macOS，3 月 4 日才登陆 Windows；4 月推出 Computer Use 时，同样是 Mac 先行。这不是说 Windows 用不了 AI，而是说 Mac 用户经常能更早体验到最新的交互方式和功能。

这种现象可能与开发者群体的设备偏好、Unix 环境、相对统一的硬件平台和商业化条件有关。其中一个很实际的原因是：程序员群体里用 Mac 的人比例很高，而 AI 工具早期的核心用户和反馈来源正是这批开发者。当一个产品最先被自己团队和最接近的开发者群体使用时，优化自然先围绕这套设备展开——Mac 上大概率会更快、更稳，功能也更完整。这不是苹果做了什么特别的事情，而是「用户在哪里，打磨就先发生在哪里」。

但对使用者来说，原因未必比结果重要。在一个产品能力以周为单位变化的行业，早一个月用上一项功能，就意味着早一个月把它融入自己的工作流。

尤其是对 AI 从业者、开发者和创作者而言，这种时间差有实际价值。它不是永久性的护城河，却是当前选择设备时值得考虑的因素。

### Unix 环境与 Agentic AI 天然契合

以前如果不是程序员，大概没有太多理由在意 macOS 是 Unix 系统。但 Agent 的出现使这个原本偏技术的优势开始惠及普通用户。

以 Codex 这样的工具为例，它并不只是在聊天框里生成代码。它会查看文件、运行 Shell 命令、安装依赖、执行 Python 脚本、调用 API、读写数据库，必要时使用 Git 管理修改。MCP、Skills 和各种 CLI 工具，又为它提供了更丰富的能力。

macOS 原生具备 Unix 环境，很多命令行工具的安装与使用方式接近 Linux。与此同时，它又有成熟的桌面应用、办公软件和创作工具。对既需要开发环境又需要日常办公的人而言，这种组合相当方便。

Windows 的 WSL、PowerShell 也已经很成熟，Linux 更不缺这方面的能力。不过 WSL 与 Windows 主机之间仍可能存在文件路径、权限、网络和运行环境的差异。Mac 的吸引力在于，很多场景下不必在两套环境之间切换。当然，它也不等同于 Linux，ARM 架构和 CUDA 兼容性仍然需要考虑。

**过去是程序员需要 Unix；现在，即使用户不会编程，他使用的 AI Agent 也可能受益于 Unix 环境。**

### 统一内存架构在本地 AI 时代的重要性上升

Apple Silicon 刚出来时，人们讨论最多的是性能和功耗。到了本地大模型时代，它的统一内存架构又有了新的意义。

传统独立显卡电脑的系统内存和 GPU 显存通常是分开的。一台有 64 GB 内存、12 GB 显存的电脑，想把模型完全放在 GPU 上推理，直接约束它的仍是那 12 GB 显存。可以用 CPU 内存卸载来扩大模型规模，但通常要付出一定的性能代价。

![图 1：独立显存架构与统一内存架构的简化对比。并非所有 PC 都使用独立显卡；可供模型使用的统一内存也小于整机标称容量。](memory-layout-zh.svg)

Mac 的 CPU 和 GPU 可以共享同一个内存池。以 70B 参数模型为例，仅按 4 bit 量化权重计算，理论上就需要约 35 GB 的空间：

$$
70 \times 10^{9} \times 4 / 8 \approx 35\ \text{GB}
$$

实际运行还需要量化元数据、KV Cache、运行时缓冲区和操作系统占用。因此，64 GB 统一内存的 Mac 在合适的模型和上下文配置下，有机会在本地运行这种量级的量化模型。苹果自己也开源了专为 Apple Silicon 设计的机器学习框架 MLX，利用统一内存简化 CPU 与 GPU 之间的数据共享。

这不代表 Mac 的推理速度一定比 NVIDIA 显卡快。训练、高吞吐推理、CUDA 软件生态，依然是 NVIDIA 的强项。Mac 的优势更多在于消费级设备上的可用内存容量、能效，以及部署本地模型的便利性。

### Computer Use：人与 AI 能不能同时工作

这可能是当前 Mac 相对于 Windows 最有意思的一个区别。Computer Use 让 AI 直接操作桌面应用：查看窗口、点击按钮、填写表单、检查结果。没有 API 的老软件，也有机会被 Agent 使用。

但如果 AI 每次操作都要占用我的鼠标、键盘和前台窗口，我就只能等它做完。原本想让 AI 替自己节省时间，结果执行任务期间电脑反而不能正常使用。

OpenAI 在 2026 年 4 月推出 Mac 端 Computer Use 时，已经支持后台操作和独立光标。其当前文档明确指出，Windows 端虽然也支持 Computer Use，但在同一个 Windows 桌面会话中会接管前台输入，不能像 Mac 端一样一边操作其他应用、一边让用户继续工作。

![图 2：前台独占与后台并行操作的差异；时间轴仅作定性示意，不代表实际速度测试。](computer-use-zh.svg)

从技术原理看，Computer Use 不只有截图识别和模拟鼠标这条路线。操作系统通常还提供辅助功能接口，可以获取控件的文本、层级和可执行动作。

| 能力 | macOS | Windows |
| --- | --- | --- |
| 视觉获取 | ScreenCaptureKit 等窗口捕获接口 | Windows Graphics Capture 等 |
| 语义操作 | Accessibility API（AXUIElement） | UI Automation（UIA） |
| 输入与自动化 | CoreGraphics、AppleScript 等 | SendInput、Win32 消息等 |

两种系统都拥有实现 Computer Use 的底层能力。Windows 的 UI Automation 同样可以在不依赖普通鼠标点击的情况下操作部分控件，而模拟系统输入的操作往往要求目标窗口处于前台。OpenAI 并未完整披露其实现，所以不能把当前产品差异直接归结为 Windows 底层不可能实现后台操作。

但从实际使用角度看，这个差异已经足够重要。比如让 Agent 整理另一个应用中的数据，同时自己继续写论文，或者让 Agent 在另一窗口里检查生成的网页，自己接着做别的事情。

**AI 的生产力价值，不只取决于它多快完成任务，也取决于它执行任务时是否占用了人的工作时间。**

### 云端算力越强，轻便的电脑反而越有价值

我过去会比较在意笔记本能提供多少本地算力。但对许多 AI 工作流来说，最耗计算资源的部分已经在云端：调用模型 API、远程训练、在云电脑上运行 Agent。本地电脑负责交互、查看结果，以及处理必须留在本地的文件。

Codex Cloud 就是一个现成的例子，任务可以运行在云端环境中，不需要本地电脑始终保持唤醒。这意味着对不少知识工作者来说，背一台厚重的高性能笔记本出门的必要性正在降低。轻便、长续航、低噪声的价值反而变得更高。需要本地长期运行 Agent 时，Mac mini 又可以承担低功耗常驻主机的角色。

云端计算与统一内存并不矛盾。适合本地的任务在本地跑，需要更强算力的任务就交给云端。这两者结合起来，才是我更看好的个人计算方式。当然，同样轻便、续航优秀的 Windows 笔记本也可以从云端化中受益。

## iPhone：Personal Agent 的数据与交互终端

相比 Mac，iPhone 在 AI 时代的价值不一定体现在它能跑多大的模型，而在于它每天跟着人，积累大量个人信息。一个足够强的 Personal Agent 不能只知道通用知识，它还需要知道我是谁、过去做过什么、现在处于什么状态。

### 系统应用的通用性：降低个人上下文的接入成本

苹果很早就建立了一套相对统一的系统应用和开发接口。以健康数据为例，无论数据来自 Apple Watch，还是接入 HealthKit 的第三方设备和应用，支持的健康数据都有机会进入同一套数据体系。

| 数据或应用 | 开发接口 | 对 Personal Agent 的价值 |
| --- | --- | --- |
| 健康 | HealthKit | 睡眠、运动、心率、身体状态 |
| 日历、提醒事项 | EventKit | 时间安排、待办、未来计划 |
| 通讯录 | Contacts | 联系人及关系线索 |
| 相册 | PhotoKit | 生活经历、视觉记录 |
| 定位 | Core Location | 当前地点、空间情境 |
| 家庭 | HomeKit | 已接入的家庭设备与状态 |

对于开发 Personal Agent 的公司而言，统一的数据类型、权限和接口可以降低适配成本。Android 也有 Calendar Provider、Health Connect 等机制，但厂商自己的健康服务、系统应用和权限实现可能存在差异，具体接入体验仍取决于产品。

想象一个健康管理 Agent：它知道我昨晚睡了多久、今天是否有会、昨天训练了哪些部位，然后再给我安排今天的运动。这与每次打开 AI 先手动输入一遍个人情况，是完全不同的使用体验。

过去记录数据，主要是为了自己看；现在记录的数据，还可以成为 AI 的上下文。对于长期积累而言，数据有没有统一的格式、能否被授权读取、换一个 AI 产品后能否继续使用，可能比单个系统应用的功能多少更重要。

### AI 软件的适配性

2023 年 ChatGPT 首先推出 iOS 客户端，两个多月后才推出 Android 客户端。类似的优先适配，在一些 AI 原生应用中也能看到。除了能不能安装，手机上的 AI 体验还有很大一部分取决于系统集成：分享菜单、桌面小组件、锁屏入口、快捷指令、Action Button，以及穿戴设备的支持。

AI 是使用频率越来越高的工具。把一篇文章复制到聊天框再提问，和在分享菜单里直接交给 AI，中间可能只差几步，但每天几十次的交互会让这些差别累积起来。

iPhone 相对集中的硬件和系统版本也有利于开发者做这些适配。这里说的是部分产品的先发和集成优势，并不是所有 AI 应用都优先支持 iOS，也不是说 Android 的系统级能力一定较差。

### 在国内，米家们积极适配 iPhone

这个问题在中国尤其值得单独讨论。小米的智能家居和家电生态很丰富，但使用米家并不要求你一定购买小米手机。米家 iOS 客户端支持设备绑定、远程控制、场景和自动化等核心能力，甚至还有 Apple Watch 版本。小米汽车和智能座舱也是同样的思路：远程控车、查看电量、空调预热、导航接力这些功能，在 iPhone 上通常都能正常使用。

过去大家默认「用小米设备就要配小米手机」，现在这个前提已经不太成立了。从米家生态、智能家居，到今天的新能源车和智能座舱，厂商都在主动适配 iPhone，而不是要求用户为了控制家里的灯和车上的屏幕去换一部手机。反过来看，如果选择华为之类的手机，部分应用和车机功能反而可能受到局限——应用生态、系统权限和跨设备联动各有自己的规则，换一个体系未必换来更完整的控制。

从核心家居功能看，iPhone 用户可以相当完整地使用米家。这样就不需要在苹果的个人设备生态和小米的智能家居生态之间二选一。至于两端具体版本的功能是否同步、研发优先级是否相同，没有足够公开证据下定论。小米手机在超级小爱、跨设备系统联动等方面也有独有优势。

这件事与 AI 的关系是：未来的 Personal Agent 不应只处理电脑和手机里的信息，还需要在获得授权后与现实中的设备交互。灯光、空调、扫地机器人和家庭传感器都是有价值的工具或信息来源。米家的跨平台兼容，为 iPhone 用户保留了接入这些能力的机会；但第三方 Agent 能否直接控制某台设备，还要看米家、设备厂商和相关接口是否开放。

### 从健康、语音到空间：持续获取个人多模态上下文

人每天产生大量信息，但绝大多数没有真正进入数字系统。开会讨论的东西、散步时产生的想法、身体的状态、看到的场景，很多信息只留在记忆里。相比要求人每天手动写日记，硬件可以降低这些信息被记录的成本。

**Apple Watch：身体状态。** 心率、活动量、睡眠等数据可以构成长期生理记录。它们在传统健康软件里主要是供人查看的统计数字；有了 AI，才更容易跨时间、跨类型关联分析。比如把最近一周的训练、睡眠和日程放在一起，辅助判断当前的训练负荷是否合理。

**AirPods：现实生活中的语言信息。** 我之前看到 Leto Bao 做的一个产品 [AideMemo](https://www.aidememo.com/)，思路很有意思：通过 AirPods、Apple Watch 或 iPhone 录制语音，再进行转写、摘要和归档，让日常交流和想法成为可检索的个人记忆。官方文档显示，启动录音之后，iPhone 锁屏仍可继续录制，直到用户主动停止。

AirPods 本身不是全天候 AI 录音设备，续航和后台权限也有限。但这个案例已经证明，现有消费级硬件可以成为个人记忆产品的输入端。涉及他人的录音必须尊重对方的知情、同意以及当地法律，不能因为个人记忆有价值就默认所有交流都应该被记录。

**iPhone 摄像头：不只是拍照。** 现在的多模态模型已经可以理解照片和视频，但真实世界不只有二维图像，还有距离、尺度、位置和空间关系。从 iPhone 15 Pro 开始，苹果支持原生空间视频拍摄：主摄与超广角两颗摄像头同时记录同一场景的不同视角，保留真实的双目视差信息，拍出来的素材在 Vision Pro 上可以重新呈现为三维影像。这跟「拍得好看」已经不是一回事——摄像头开始记录的是场景本身的几何结构。在 AI 时代，iPhone 的摄像头值得被重新审视。

Pro 系列搭载的 LiDAR 激光雷达则补上了深度信息。配合 ARKit 和 RoomPlan，iPhone 能够对现实环境做三维重建：RoomPlan 可以生成包含家具、尺寸等信息的房间模型，Vision Pro 上的 ARKit 还提供场景重建与空间定位能力。

**Vision Pro：把空间内容呈现出来。** 把这几条线放在一起看，苹果实际上已经建立了一套从空间信息采集、环境建模到空间内容呈现的技术体系——iPhone 负责采集，ARKit 与 RoomPlan 负责建模，Vision Pro 这样的头显负责把三维内容重新呈现出来；未来更轻量的智能眼镜，有机会把这一层变成随时随地的入口。

这也是我最愿意把它和 Spatial Intelligence（空间智能）、World Model（世界模型）放在一起讨论的地方。这类模型要真正理解物理世界，仅靠平面图像并不够，它还需要知道东西在哪里、有多大、彼此如何遮挡、人又处在什么位置。三维空间信息正是这种理解的原材料。今天，这些技术主要服务于摄影、增强现实和沉浸式体验；但未来随着空间智能和世界模型的发展，三维空间信息也可能成为 Personal Agent 理解物理世界的重要上下文——比如拍一下房间，AI 就能依据真实尺寸给出家具布局建议，而不只是从一张照片里猜。

![图 3：个人 AI 系统的可能形态。并非苹果已经实现的完整产品；各数据与工具均需要适当接口、权限和用户授权。](personal-ai-stack-zh.svg)

把 Apple Watch、AirPods、iPhone、Vision Pro 和智能眼镜放在一起看，分工就清楚了：Apple Watch 记录人的生理状态，AirPods 采集语言信息，iPhone 记录视觉与空间信息，Vision Pro 负责把空间内容呈现出来，智能眼镜则让这种呈现更贴近日常。苹果硬件生态的价值，正在从提供消费电子功能，进一步延伸到为个人 AI 提供多模态感知能力。

### 价格：算力需求正在重算性价比

AI 时代，算力需求也在推高手机硬件的价格。要跑本地模型、要更大的内存和更强的 NPU，成本最终会落到整机售价上。对安卓阵营里那些软件与服务利润很薄的厂商来说，硬件走量本就是主要收入来源，成本上涨时涨价幅度往往更大，性价比反而下降。iPhone 的绝对价格不低，但它的溢价更多由生态和长期体验支撑，受这一轮硬件成本上涨的冲击相对有限。当「能跑 AI 的手机」越来越贵，买哪台手机这件事，也需要把性价比重新算一遍。

### 其他值得关注的能力

一个是 App Intents 和快捷指令。前者允许开发者把应用中的操作以结构化方式暴露给 Siri、快捷指令等系统功能，与大模型的 Tool Calling 有一定共通性。如果应用本身提供了创建任务、查询日程的接口，就没有必要每次都让 AI 截图识别按钮、模拟点击。不过，第三方模型并不能自动调用所有 App Intents，Android 也在发展类似的能力。

另一个是手机和电脑的远程协同。未来很多任务可能在手机上发起，在 Mac 或云电脑上执行，再由手机查看进度、补充要求和确认关键操作。这种模式已经在一些 Agent 产品中出现，Windows 主机同样可以支持远程控制。手机上的任务不再受限于手机自身能运行哪些桌面软件。
